- **Two runs of one skill no longer run its box's `post_start` at the same time** (#3555). A run that reached a skill's box while the first deploy was still running `post_start` started a second `post_start` in the same box, and could remove the not-prepared key before the first one finished, so a failing first `post_start` left the box unmarked and the next run reused it silently. The deploy now holds a per-box lock until its `post_start` is done, and a run that would reuse the box waits for it (or stops waiting when its own request is cancelled) and then reads the box again. When the daemon cannot write the not-prepared key, the failure is now reported in the `post_start` error, or as a warning in an async deploy's message, instead of only in the daemon log; the deploy still goes on and no box is deleted.
