- **A recipe whose `post_start` failed silently now fails its deploy** (#3545, follows #3542). Every `post_start` in the catalog already runs under `set -euo pipefail`, so a recipe that stopped partway and was reported deployed is now reported failed (synchronous deploy: an `Internal` error naming the box and exit status). Skill and crew runs share the same path and are affected the same way. A failed `post_start` also skips exposing the recipe's ports (fail closed): an asynchronous deploy leaves the box running with no route, and the daemon journal line now says `ports were not exposed`. A step that exits 0 with output past the exec capture cap still succeeds, but a timeout or transport error that also exceeded the cap now fails the step instead of passing. The `ollama` recipe now waits for the server (60 probes, each bounded to 5s, 2s apart) before pulling the model and fails with a clear message if it never comes up.
