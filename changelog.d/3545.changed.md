- **A recipe whose `post_start` failed silently now fails its deploy** (#3545, follows #3542). Every `post_start` in the catalog already runs under `set -euo pipefail`, so a recipe that stopped partway and was reported deployed is now reported failed (synchronous deploy: an `Internal` error naming the box and exit status). Skill and crew runs share the same path and are affected the same way. A failed `post_start` also skips exposing the recipe's ports (fail closed): an asynchronous deploy leaves the box running with no route, and the daemon journal line now says `ports were not exposed`. Output past the exec capture cap is still tolerated, but only when it is the only problem; a timeout or transport error that also exceeded the cap now fails the step instead of passing. The `ollama` recipe waits up to 120s for the server before pulling the model and fails with a clear message if it never comes up.
