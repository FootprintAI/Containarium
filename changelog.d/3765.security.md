- **The coding-agent guardrail hook redacts a failed shell command's output** (#3765). A failed `Bash` call reached the model as an error result, which Claude Code does not pass through `PostToolUse`, so `cat .env; false` sent the raw values to the model (observed live in `docs/verification/2026-W48-guardrail-hook.md`). `containarium guardrail hook PreToolUse` now prefixes each `Bash` command with an `EXIT` trap that prints `[exit status N]` for a non-zero status and exits 0, so the output is redacted like any other result, and the session context tells the model what that line means. On by default; `--wrap-failed-commands=false` turns it off. The permission prompt shows the prefix. A command with its own `EXIT` trap, a background command and `PowerShell` are not covered.
