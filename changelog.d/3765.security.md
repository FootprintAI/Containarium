- **The coding-agent guardrail hook redacts a failed shell command's output where it can** (#3765). A failed `Bash` call reached the model as an error result, which Claude Code does not pass through `PostToolUse`, so `cat .env; false` sent the raw values to the model (observed live in `docs/verification/2026-W48-guardrail-hook.md`). `containarium guardrail hook PreToolUse` now prefixes a `Bash` command with an `EXIT` trap that prints `[exit status N]` for a non-zero status and exits 0, so the output is redacted like any other result, and the session context tells the model what that line means. It is applied only where Claude Code will run the wrapped command: in `bypassPermissions`, or in `default`, `acceptEdits` or `dontAsk` mode when the managed, user or project settings allow `Bash` or `Bash(*)` (only managed settings count under `allowManagedPermissionRulesOnly`), and no `Bash` ask rule is set. Under narrower rules (for example `Bash(git status *)`), rules given only with `--allowedTools`, a `Bash` ask rule, or `plan` or `auto` mode, commands are left as they are and a failed command's output still reaches the model. On by default; `--wrap-failed-commands=false` turns it off. A command with its own `EXIT` trap, `exec`, a shell killed by a signal, a background command and `PowerShell` are not covered.
