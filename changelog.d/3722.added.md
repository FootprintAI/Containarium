- **`ListBackends` says why a backend is unhealthy** (#3722). `BackendInfo.unhealthy_reason` is a typed `BackendUnhealthyReason` set next to `healthy` and derived from the same inputs, so `healthy` is true exactly when it is `UNSPECIFIED`: `NO_RECENT_HEARTBEAT` (a peer that was healthy no longer passes the sentinel's health checks), `NEVER_SEEN` (a peer that has not been healthy since the daemon started tracking it) or `DRIVER_ERROR` (the local Incus liveness probe is failing). `containarium backends list`, `backends get` and `pool list` print the reason in the `HEALTH` column, and the MCP `list_backends` and `get_backend` tools name it. A daemon that predates the field leaves it `UNSPECIFIED` on an unhealthy backend, shown as a bare `✗`.
