- **`WriteBoxFile` writes into the run user's home on a box with a recorded
  tool-access level** (#3678). Platform runs on such a box execute as the
  unprivileged run user (`ctn-run`), which could not read a file placed in the
  owner's home with mode 0600, so an attachment sent with a run was invisible
  to it. `WriteBoxFile`, `WriteBoxFileStream`, `containarium code put-file` and
  the MCP `put_file` tool now place the file in the run user's home, placed and
  owned by the run user, with the same path rules, modes, atomic rename and
  checksum check. The run user's home is `0700`, so no other non-root user on
  the box can read the file. The run user is created first if the box has not
  had a run yet. `path` is relative to the run user's home, as a run's
  `workdir` already is on such a box, and the response's `path` is where the
  file is. An unreadable level or a run user that cannot be created is
  `UNAVAILABLE` and writes nothing. A box with no recorded level is unchanged.
  Advertised as the `box_files_run_user` capability. See
  `docs/BOX-RUN-API.md`.
