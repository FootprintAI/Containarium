# Design: capability-gated subdomain claims and binding

**Date:** 2026-10-27

**Status:** proposed (design only; no implementation)

**Issue:** [#2145](https://github.com/FootprintAI/Containarium/issues/2145); follows the tool decision in [#1971](https://github.com/FootprintAI/Containarium/issues/1971)

**Stack:** existing Go CLI and platform MCP, protobuf/gRPC with grpc-gateway; a downstream hosted control plane owns claim storage and policy.

## Decision and motivating workflow

Choose **B: publish a capability-gated contract and two tools in this repository; keep reservations in the hosted control plane**. The OSS daemon advertises `supported = false` and does not store or enforce claims. A hosted server implements the same proto and OSS-shaped REST paths, advertises support only when its claim ledger and policy checks are ready, and enforces every mutation. `containarium subdomain ...` works against a supporting server and gives a clear unsupported error against a self-hosted daemon.

A concrete agent workflow needs the separate claim step: an agent is preparing a release under a user-approved, stable hostname before the replacement container exists. It claims `preview.example.com`, receives a claim ID and an expiry, builds and tests the replacement container, then binds the claim ID to that container's port. On a later replacement it binds the **same ID** to the new container and port, keeping the public name. `expose_port` remains the short claim-and-bind path when a container is already ready. An abandoned preparation releases automatically at expiry; an active release does not.

This feature reserves **names under a hosted managed zone**. It is not a general reservation service for arbitrary DNS names. Self-hosted operators have no tenant quota or shared namespace to reserve against; they continue to use `route add` and `expose-port` for their own domains.

| Option | Assessment |
| --- | --- |
| A — daemon owns reservations | Makes the tools available on every daemon, but creates a second claim ledger and policy engine beside the hosted control plane's existing quota and tenant authority. It would also impose TTL and quota semantics on self-hosted routes that do not need them. Reject. |
| **B — capability-gated tools, hosted ownership** | Shares the CLI, MCP, and proto contract while keeping admission, ownership, and cleanup at the component that already has the tenant namespace and quota. Older/self-hosted servers fail clearly. **Choose this.** |
| C — hosted-only tools | Keeps hosted policy local, but splits the agent and CLI surfaces and leaves this repository's MCP server unable to perform the sprint owner's chosen workflow. It also invites a second, unversioned API shape. Reject. |

The open-core boundary is explicit: OSS defines interoperable API/client/tool shapes and an unsupported capability response; hosted code supplies persistence, quota policy, tenant authorization, expiry, and coordination with daemon routes. This does not assume a particular hosted reconciler already exists. A capability is a server response, not an inference from a `ctnr_` token or a hostname. An older server returning `Unimplemented`/404 for discovery is treated as unsupported. Neither the MCP process nor the CLI is an authority for quota or ownership. Hosted tenant credentials must not bypass this boundary by calling the daemon's admin route API directly; only a trusted hosted service may do that.

## Existing architecture and constraints

- `proto/containarium/v1/network.proto` defines `NetworkService` route RPCs with `google.api.http`; `make proto` generates Go, grpc-gateway, and `api/swagger/containarium.swagger.json`. `internal/client/{grpc,http}.go` and `internal/mcp/client.go` consume those paths. New public endpoints follow this route, including OpenAPI annotations.
- `internal/app/route_store.go` stores `RouteRecord` in PostgreSQL with **non-null target IP and port**, `active`, and `created_by`. `internal/server/network_server.go` writes it, then `internal/app/route_sync.go` projects routes to Caddy. `active = false` is a disabled route, not proof of a bare reservation. The daemon's `GetRoutes` also has a Caddy fallback; neither source can represent an unbound claim. Do not insert placeholder routes into either one.
- `AddRoute`/`UpdateRoute`/`DeleteRoute` are admin-only in the daemon and require `routes:write`; `GetRoutes` requires `routes:read`. `RouteStore.Save` checks creator conflicts on a full domain. The current `GetRoutes` route-store branch sets `req.Username` for non-admin callers but does not apply it to the returned rows; its Caddy fallback does filter. A hosted control plane must filter **every** list result from the authenticated tenant and authorize claim, bind, and release itself. It cannot rely on the daemon's current listing filter or on an MCP-side scope filter.
- `internal/cmd/expose_port.go` and `internal/mcp/tools.go` already call the same `pkg/core/expose.Run` through transport adapters. `expose_port` resolves a container IP, then uses `AddRoute`; it has no bare-claim RPC. The new CLI verbs must precede the tools and share one Go claim/bind function with them, using typed adapters for gRPC and HTTP.
- `list_routes` and `delete_route` are the existing list/release tools. [#1971](https://github.com/FootprintAI/Containarium/issues/1971) found downstream bugs where inactive claims were hidden and deletion by `fullDomain` silently failed. The independent tool-description change is tracked by [#2160](https://github.com/FootprintAI/Containarium/issues/2160); this design does not add `list_subdomains` or `delete_subdomain`.

## Proposed contract (proto first)

Add the following to `NetworkService` in `network.proto`, with `google.api.http` and OpenAPI operation annotations. These are **proposed** names and fields, not current RPCs. Use `google.protobuf.Timestamp` for UTC expiry and protobuf enums for states; no string-valued state/kind field.

| RPC and REST mapping | Request | Response and behavior |
| --- | --- | --- |
| `GetSubdomainCapabilities` — `GET /v1/network/subdomains/capabilities` | empty | `supported` and `detail`. Requires `routes:write`, matching the actions it advertises. OSS returns `supported = false`. Policy limits stay in hosted configuration; capability discovery is not a second quota API. |
| `ClaimSubdomain` — `POST /v1/network/subdomains/claims` | `domain` (label or managed-zone FQDN) | `SubdomainClaim {id, full_domain, state, created_at, expires_at}`. Requires `routes:write`. Hosted accepts only canonical names in a configured managed zone; no target is required. |
| `BindSubdomain` — `POST /v1/network/subdomains/claims/{claim_id}/bind` | `claim_id`, `username` (container identifier), `container_port` (1–65535), optional `description` | Updated `SubdomainClaim` plus `ProxyRoute`. Requires `routes:write`. The server resolves the current container IP and verifies that the target belongs to the claim's tenant; it never accepts an agent-supplied target IP. Rebinding a bound ID replaces its target. |

`SubdomainClaimState` has `UNSPECIFIED`, `RESERVED`, and `BOUND`. `expires_at` is present only in `RESERVED`; `BOUND` never has an expiry. An expired claim returns `FailedPrecondition` until cleanup; after release it is absent from normal listing and bind returns `NotFound`. Audit history may retain a tombstone. `id` is an opaque immutable identifier (UUID is suitable), while `full_domain` is the canonical display and delete key. Reject reserved/system labels, wildcards, non-managed FQDNs, and names that collide after case folding and normalization. The server derives tenant identity from its authenticated principal; request fields cannot select another owner.

Claiming a name already `RESERVED` by the same tenant returns the same ID and original expiry; it does not renew it. Claiming the tenant's already `BOUND` name returns `FailedPrecondition` with guidance to use its ID from `list_routes` for rebinding. Another tenant's name returns `AlreadyExists` without revealing its claim ID.

Extend `ProxyRoute` additively with optional claim metadata: `claim_id`, `SubdomainClaimState claim_state`, and `google.protobuf.Timestamp claim_expires_at`. This is a shared **response envelope**, not a daemon reservation table. A hosted `GetRoutes(active_only = false)` returns one row per visible claimed name, including a `RESERVED` row with `active = false` and no target. `BOUND` rows contain the selected target and claim ID; `active` must not imply that a daemon write succeeded when it is still pending. Ordinary OSS disabled routes leave claim fields unset, so callers do not mistake them for expiring reservations. `active_only = true` excludes unbound claims. For claim recovery, callers omit the `username` target-container filter and the hosted server applies the authenticated tenant filter. The response must use the same `full_domain` that `DeleteRoute` accepts. Preserve proto field numbering and JSON names; old clients ignore the new fields.

The supporting server must mirror these exact RPCs and HTTP paths, enum JSON encoding, status codes, and response shapes. It must also mirror `GetRoutes` and `DeleteRoute` semantics for claims. `DeleteRoute(full_domain)` releases an unbound claim after tenant authorization. For a bound claim, the hosted server holds the name while removing the daemon's route and releases the name only after authoritative route removal is confirmed; a failed or pending removal does not report a completed release. There is no atomic transaction across the hosted store and daemon. Only a truly absent name is an idempotent success. A mismatched label/full hostname or ownership conflict must not report a successful release. `expose_port`/`AddRoute` must use the **same hosted name ledger and admission checks**, so legacy claim-and-bind cannot bypass quota or take a reserved name. The OSS daemon's existing admin route API remains a route API and gains no hosted quota behavior.

Suggested errors: `AlreadyExists` for a name held by another owner, `ResourceExhausted` for quota admission, `PermissionDenied` for a claim or target outside the caller's tenant, `FailedPrecondition` for bind on an expired claim or release while route removal is pending, `InvalidArgument` for invalid names/ports, and `Unimplemented` when the feature is unsupported. Preserve these through grpc-gateway and both clients. Do not return a foreign claim ID in an error.

## CLI and MCP surface

Implement CLI first: `containarium subdomain status`, `containarium subdomain claim <domain>`, and `containarium subdomain bind <claim-id> <username> --container-port <port> [--description ...]`. All use the generated client through the existing gRPC/`--http` selection. The claim and bind Cobra handlers and MCP handlers call the same Go validation/orchestration functions; MCP only maps JSON arguments and formats typed results. The server remains authoritative for validation and authorization.

| MCP tool | Input JSON schema | Output |
| --- | --- | --- |
| `claim_subdomain` (`routes:write`) | Object with required `domain: string`; no target fields and no arbitrary TTL | `id`, `fullDomain`, `state: SUBDOMAIN_CLAIM_STATE_RESERVED`, `expiresAt` |
| `bind_subdomain` (`routes:write`) | Object with required `claim_id: string`, `username: string`, `container_port: integer`; optional `description: string` | Claim ID/state plus bound `fullDomain`, container name, port, and route status |

The MCP input schemas use `type: object`, typed `properties`, and `required`
exactly as listed above. `bind_subdomain.container_port` has `minimum: 1` and
`maximum: 65535`; both schemas set `additionalProperties: false`. The bind
result reports whether the daemon accepted the route write, separately from
the durable `BOUND` claim state. This avoids describing an incomplete bind
as a live URL.

Both tool descriptions explain the capability requirement and tell an agent to call `list_routes` with `active_only = false` and no `username` filter to recover a claim ID, and `delete_route(fullDomain)` to release a name. Do not add `list_subdomains` or `delete_subdomain`. Scope-filter `tools/list` as today, and check the advertised server capability before either write. Unsupported discovery (including an old daemon) returns a specific “subdomain claims unavailable on this server” error with no mutation. The server repeats the check and enforces `routes:write`, so cached or forged client capability state grants nothing. `routes:read` covers `list_routes`; `routes:write` covers discovery, claim, bind, and delete. Agents that need ID recovery require both read and write scopes. Hosted tenant authorization applies in addition to scopes. The OSS daemon should reject claim/bind rather than silently turn them into routes.

## Hosted state, quota, and anti-hoarding policy

The hosted control plane is the **sole** owner of the claim ledger, quota counter, TTL clock, cleanup worker, and tenant authorization. It must use its own transactional datastore as the source of truth for names and durable binding intent, then coordinate route writes with the daemon. The daemon continues to own route execution and Caddy sync, but neither the daemon, MCP server, nor a client-side timer decides that a claim has expired. A single unique key on canonical `full_domain` and transactions/row locks (or equivalent compare-and-swap) serialize claim, bind, delete, and cleanup.

The policy goal is to bound *unbound* name holding without changing the lifetime of a real route. No repository data establishes an optimal numerical TTL or rate. The hosted operator should validate the pilot values below against measured time from claim to bind, expiry frequency, legitimate concurrent preparations, and quota pressure before broad rollout. Values belong in hosted configuration, never in an agent-supplied TTL or the OSS daemon.

Recommended pilot policy:

| Rule | Recommendation and enforcement |
| --- | --- |
| Total namespace quota | Count every `RESERVED` and `BOUND` managed-zone name against the tenant's existing total subdomain quota. Admit atomically in the hosted claim ledger, including `expose_port`/`AddRoute`. Do not create a second quota counter in the daemon. |
| Unbound quota | Start with **one** `RESERVED` name per tenant, within the existing total quota. The motivating workflow stages one future hostname; additional simultaneous preparations need evidence or a plan-specific override. Enforce in the hosted claim transaction against the tenant, not per agent/token. |
| TTL | Start with **24 hours** for `RESERVED`, an overnight preparation window rather than a long-term name hold. Treat this as a pilot assumption: measure claim-to-bind duration and check that the legitimate tail plus recovery buffer fits before rollout; otherwise change the value. Show absolute `expires_at` in claim and `list_routes` responses. A retry of the same owner/name returns its original ID and expiry. `BOUND` has no TTL. |
| Renewal | **No renewal in the initial contract.** Automatic renewal or renewing through repeated claims would defeat expiration, while an extra RPC/CLI action is unjustified by the named workflow. If telemetry shows legitimate preparations need more than the chosen TTL, evaluate a separate, explicit, bounded renewal design then. Never expire a bound route as a substitute. |
| Claim churn | Apply tenant-level API write throttling where available; do not invent a daily claim count for this feature. Monitor unique claims, releases, and repeated reclaims per tenant. If churn bypasses the one-slot limit in practice, add a creation rate or same-name cooldown with a threshold based on observed legitimate turnover. |

The hosted worker scans only `RESERVED` rows whose expiry is in the past. It conditionally deletes a row under a lock/version check **after** verifying that no binding intent or daemon route exists for its canonical full domain. If a route exists despite `RESERVED` state, or route state cannot be checked, quarantine the claim and alert for reconciliation; never delete the route. Binding and cleanup serialize on the claim row, so a bind that wins first makes it `BOUND` and ineligible for expiry, while cleanup that wins first makes bind fail with a clear expired/not-found result. A disabled `BOUND` route is still bound and is never TTL-cleaned. Cleanup releases the unbound quota slot and removes only the reservation listing; it must not call the daemon's `DeleteRoute` on an expired name. Admission should reclaim expired rows through this same guarded path before counting quota; merely excluding an expired row from quota while its unique name remains held creates inconsistent behavior.

For bind/rebind, verify that the target is an existing, running container owned by the claim's tenant and has a current IP; otherwise leave the claim `RESERVED` and return a precondition error. Then durably record `BOUND` and the intended target in the hosted claim transaction, preserving claim ID and tenant owner, before applying the mapping to the daemon. `BOUND` means a target has been durably selected; it does not promise Caddy is already serving traffic, just as today's `AddRoute` returns before Caddy sync. A failed daemon write must leave the name protected and retryable, and the API must report that routing was not yet accepted rather than claim a live route. The hosted implementation may use its existing reconciliation path or add a retry/outbox mechanism; this document does not assume either already exists. If the hosted ledger and daemon disagree, reconcile or alert; fail closed on deletion. Explicit `delete_route` is the only normal way to remove a bound claim and its route. Existing hosted names must be backfilled or reconciled into the single ledger before the new admission path is enabled, so quotas and uniqueness include legacy `expose_port` routes. A tenant could still bind a real but unused container to hold a name; expiry must not remove it, so the total-name quota and hosted abuse review are the safeguards for bound-name squatting.

## Implementation sequence and acceptance checks

These are **proposed follow-up issues**. #2145 asks for implementation issues, but they are intentionally not filed as part of this design-only work without approval.

1. **Proto, capability, and clients (OSS).** Add the three RPCs/messages/enum and additive `ProxyRoute` fields; annotate HTTP/OpenAPI; regenerate with `make proto`; wire gRPC/HTTP/MCP clients. OSS advertises unsupported and returns `Unimplemented` for claim/bind. Acceptance: `buf lint`/breaking check, generated-code diff, gRPC and REST contract tests, old-server discovery fallback, enum/expiry JSON round trips.
2. **Hosted ledger and route compatibility (downstream).** Implement one canonical name ledger, tenant-scoped claim/bind/delete/list, backfill legacy names, and use it for `expose_port`/`AddRoute`. Ensure tenant credentials cannot bypass it through direct daemon admin routes. Acceptance: concurrent claims admit one owner; quotas cannot be bypassed through legacy paths; `list_routes` shows only the caller's bare claims with IDs and expiry; `delete_route(fullDomain)` actually releases them and holds bound names until daemon route removal succeeds; cross-tenant claim/target/delete fail; bind/rebind preserve the ID; failed daemon writes retain the bound claim and report incomplete routing.
3. **Hosted expiry worker and pilot policy (downstream).** Implement the one-slot pilot cap, configured TTL, conditional cleanup, metrics/audit, and discrepancy quarantine. Acceptance: fake-clock tests cover exact expiry, retry without TTL refresh, bind/cleanup races, disabled and active bound routes, failed route-state checks, and a ledger/route mismatch where the route is never deleted. Record claim-to-bind durations and expiry rates before changing the pilot values; no renewal path ships initially.
4. **CLI and MCP surface (OSS).** Land CLI verbs and a shared Go claim/bind function, then register exactly the two chosen MCP tools with `routes:write`. Acceptance: both transports and both front ends return the same claim/bind result; capability and scope gating work; unsupported self-hosted targets give a clear error; `list_routes`/`delete_route` remain the recovery/release workflow; no extra subdomain list/delete tool. Keep the independent wording change in #2160.
5. **Route-list tenant filter (OSS bug fix).** Apply the authenticated tenant filter in the route-store branch of `GetRoutes`, independently of this feature. Acceptance: non-admin `routes:read` callers cannot list another tenant's route from PostgreSQL; admin listing and the Caddy fallback remain correct. Hosted claim listing must enforce its own tenant filter regardless of this fix.

No production code, proto, generated file, or GitHub issue is changed by this document.
